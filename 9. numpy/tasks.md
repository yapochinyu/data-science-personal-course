## Ключевые идеи

1. `ndarray` — это непрерывный буфер сырых чисел одного типа плюс метаданные (`dtype`, `shape`, `strides`). `list` — массив указателей на разбросанные по памяти Python-объекты. Отсюда вся разница в памяти и скорости.
2. NumPy быстрее не «потому что на C», а по четырём причинам: нет боксинга/анбоксинга объектов, один вход в C-код вместо N итераций интерпретатора, непрерывная память хорошо ложится в кэш, однородный тип позволяет SIMD и передачу в BLAS. Следствия: `np.vectorize` не ускоряет, а на массиве из 10 элементов NumPy может быть медленнее чистого Python.
3. Базовая индексация (целые индексы, срезы, `None`) **всегда** возвращает view; продвинутая (массив индексов, булева маска) — **всегда** копию. Критерий: view возможен, только если адреса выбранных элементов описываются одной формулой `base + Σ idx·stride`.
4. Практическое следствие view: `b = a[1:3]; b[0] = 100` меняет `a`. И наоборот: `a[a<0] = 0` меняет массив, а `b = a[a<0]; b[:] = 0` — нет, потому что `b` уже копия. Проверять надо через `np.shares_memory`, а не через `.base`.
5. Для масок нужны побитовые `&`, `|`, `~` со скобками: `and`/`or` вызывают `__bool__()`, который для массива больше одного элемента неоднозначен. Ловушка: `~` на целочисленном массиве — побитовая инверсия (`~1 → -2`), а не смена знака.
6. `axis` — это ось, которая схлопывается и исчезает из `shape`. `keepdims=True` оставляет её длиной 1, чтобы результат агрегации остался broadcastable к исходному массиву. `X.mean(axis=0)` — среднее по признакам, `axis=1` — по объектам.
7. Правила broadcasting: формы выравниваются справа, недостающие левые оси дополняются единицами, по каждой оси размеры равны или один равен 1, результат — максимум. `np.newaxis`/`None` — главный инструмент управления.
8. Broadcasting не копирует входы (растянутая ось получает `stride = 0`), но **результат операции материализуется полностью**. Опасен не механизм, а форма результата: перед `A[:,None,:] - B[None,:,:]` надо в уме посчитать `n·m·d·itemsize`.
9. `reshape` и `ravel` возвращают view, если новую форму можно выразить через существующий буфер, иначе копию; `flatten` — всегда копия. `.T` — view (переставлены `shape` и `strides`), но после него массив не C-непрерывен, поэтому `a.T.reshape(-1)` обычно копирует.
10. `dtype` определяет память и поведение: `float32` вдвое легче и быстрее `float64` и обычно достаточен для ML, но подводит на длинных суммах и вычитании близких чисел. Целые переполняются молча с заворачиванием (`uint8: 250+10 → 4`) — классический баг в изображениях.
11. In-place `a += 0.5` на int-массиве **падает**, потому что результат пишется в тот же буфер. А `a[:] = a + 0.5` не падает и молча обрезает дробную часть — непадающий вариант опаснее падающего.
12. Векторизация — это не «обернуть цикл», а переформулировать задачу через готовые C-реализации: ufunc, маски, `np.where`, матричное умножение, `bincount`. `np.vectorize` даёт синтаксис, но внутри всё равно Python-цикл.
13. `*` — поэлементное умножение, `@` — матричное. При совпадающих формах `*` не упадёт, а просто посчитает не то. Для 3D+ `@` работает как батч умножений по двум последним осям.
14. NaN: `np.nan != np.nan`, один NaN отравляет всю агрегацию, `argmax` при NaN возвращает индекс NaN. Лечится `nanmean`/`nanargmax` или маской `~np.isnan(a)`; `np.isfinite` ловит ещё и `inf`. Сравнивать float результаты нужно через `np.isclose`/`allclose`, а не `==`.
15. Численная устойчивость в двух местах, которые спрашивают: softmax — вычесть построчный максимум перед `exp` (сдвиг сокращается в дроби); logloss — `np.clip(p, eps, 1-eps)` перед `log`, иначе `log(0) = -inf`.
16. Инструменты ранжирования: `argsort` даёт **индексы** (это позволяет синхронно переставить несколько связанных массивов), `argpartition` даёт top-k за `O(n)` вместо `O(n log n)`, `bincount` и `unique(return_inverse=True)` — это group-by без циклов и без pandas.
17. Попарные расстояния считают через `‖x−y‖² = ‖x‖² + ‖y‖² − 2·x·y`: промежуток `(n,m)` вместо `(n,m,d)`, тяжёлая часть уходит в BLAS. Плата — вычитание близких чисел, отсюда обязательный `np.maximum(dist_sq, 0)` перед `sqrt`.
18. Границы NumPy: массив фиксированного размера, поэтому `np.append` в цикле даёт квадратичную сложность (накапливать надо в список); `dtype=object` убивает все преимущества; только CPU и никакого автодифференцирования.
