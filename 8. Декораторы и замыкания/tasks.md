## Ключевые идеи

1. Функция в Python — объект первого класса: имя без скобок (`f`) — ссылка на объект-функцию, имя со скобками (`f()`) — её вызов. Функцию можно присвоить переменной, положить в список/словарь, передать аргументом и вернуть из другой функции.
2. Вложенная функция ищет имена по правилу LEGB (Local → Enclosing → Global → Built-in): переменные объемлющей функции она **читает** свободно.
3. Замыкание — внутренняя функция, которая продолжает пользоваться переменными внешней после того, как та завершилась. Переменные не умирают, потому что объект-функция держит на них ссылку; лежат в `func.__closure__[i].cell_contents`.
4. Каждый вызов внешней функции создаёт новое, независимое замыкание со своим набором запомненных переменных (`double` и `triple` не мешают друг другу).
5. Замыкание хранит **ссылку на переменную**, а не снимок её значения — отсюда классическая ловушка с lambda в цикле: все замкнули одну и ту же `i` и после цикла видят её последнее значение. Лечится фиксацией через дефолтный аргумент (`lambda i=i: i`), потому что дефолты вычисляются в момент определения.
6. Читать замкнутую переменную можно молча, а **присвоить** ей — только объявив `nonlocal`: иначе Python считает имя локальным и падает с `UnboundLocalError`. `nonlocal` — про объемлющую функцию, `global` — про модуль. Мутация изменяемого объекта (`items.append(x)`) в `nonlocal` не нуждается — там нет присваивания имени.
7. Замыкание — способ сделать функцию с памятью или настройкой без класса: счётчик, порог, кеш. Когда состояние маленькое — короче, чем класс с `__call__`.
8. Декоратор — обычная функция, которая принимает функцию и возвращает новую функцию (обычно обёртку), делающую что-то до/после и вызывающую оригинал внутри. Оригинал не исчезает — обёртка держит его через замыкание.
9. `@deco` над `def f` — синтаксический сахар для `f = deco(f)`; выполняется **один раз в момент определения функции** (то есть при импорте модуля), а не при каждом вызове. Отсюда: `print` в теле декоратора печатается один раз, `print` в теле wrapper — на каждый вызов.
10. Универсальная обёртка — `def wrapper(*args, **kwargs)` + `return func(*args, **kwargs)`: без звёздочек она сломается на функции другой сигнатуры, без `return` — тихо начнёт возвращать `None`.
11. После декорирования под именем живёт обёртка, поэтому `f.__name__` даёт `'wrapper'`, а докстринг теряется; это ломает логи, `help()` и фреймворки (FastAPI, pytest), которые читают `__name__`. Лечится `@functools.wraps(func)` над wrapper — копирует `__name__`, `__doc__`, `__module__`, `__wrapped__`.
12. Кеш-декоратор: словарь живёт в замыкании, ключ — кортеж аргументов, значение — результат. Ограничение: аргументы должны быть хешируемыми (`tuple` можно, `list` нельзя — `TypeError: unhashable type`). Готовый вариант — `functools.lru_cache`.
13. Декоратор с параметрами — три уровня вложенности: фабрика принимает параметры и возвращает декоратор, декоратор принимает функцию и возвращает обёртку. `@retry(times=3)` = `f = retry(times=3)(f)` — два вызова подряд.
14. Стек декораторов применяется снизу вверх: `@a @b @c def f` → `f = a(b(c(f)))`; при вызове управление идёт снаружи внутрь. Порядок меняет смысл: `@timer` поверх `@cache` меряет и попадания в кеш, `@cache` поверх `@timer` при попадании в кеш таймер вообще не вызывает.
15. Декораторы — не экзотика, а то, что уже используется каждый день: `@property`, `@contextmanager`, `@lru_cache`, `@app.get(...)`, `@pytest.mark.parametrize` — всё это функции, возвращающие функции.

> В этом порядке timer снаружи: он вызывается всегда, включая попадание в кеш → на втором вызове увидишь время близкое к нулю. Если поменять местами (`memoize(timer(...))`) — кеш снаружи, при попадании timer вообще не вызывается → второй вызов ничего не напечатает.

> [!hint]- Подсказка 3
> Чтобы видеть экономию, timer должен быть снаружи (`@timer` сверху). Сформулируй правило одной фразой: «верхний декоратор — самый внешний слой; при вызове управление идёт снаружи внутрь».

### Задача 14 (идеи 1, 8, 13) — код руками (реестр — полезный паттерн)
Напиши систему регистрации трансформаций: декоратор `@register('normalize')` кладёт функцию в глобальный словарь `REGISTRY` под указанным именем и **возвращает функцию неизменённой**. Зарегистрируй три функции, затем напиши `apply_pipeline(data, steps)`, применяющий по именам: `apply_pipeline(x, ['normalize', 'clip'])`. Отдельно ответь: почему `register` может вернуть исходную функцию без обёртки?

> [!hint]- Подсказка 1
> Здесь декоратор нужен не ради обёртки, а ради побочного эффекта — записи в словарь в момент определения функции.

> [!hint]- Подсказка 2
> Два уровня (декоратор с параметром): `def register(name): def decorator(func): REGISTRY[name] = func; return func; return decorator`. Обёртки нет вообще.

> [!hint]- Подсказка 3
> Возвращать оригинал можно, потому что декоратор обязан вернуть *что-то*, что станет новым значением имени — но никто не требует, чтобы это было новое поведение. `apply_pipeline`: цикл по `steps`, `data = REGISTRY[step](data)`; подумай, что делать при неизвестном имени (`KeyError` или свой понятный `ValueError`?).

### Задача 15 (идеи 3, 6, 8, 10, 11 — интеграционная) — код руками
Напиши декоратор `@rate_limited(max_calls)`: он разрешает функции выполниться не более `max_calls` раз, а на всех последующих вызовах бросает `RuntimeError('лимит вызовов исчерпан')`. Требования: счётчик живёт в замыкании (не глобальная переменная), работает с любой сигнатурой, метаданные сохранены, счётчик у каждой декорированной функции свой. Продемонстрируй независимость на двух разных функциях.

> [!hint]- Подсказка 1
> Три уровня; счётчик заводи в теле `decorator` (не в теле фабрики и не в wrapper) — подумай, почему это принципиально для «свой у каждой функции».

> [!hint]- Подсказка 2
> Внутри wrapper счётчик нужно **увеличивать**, то есть присваивать → потребуется `nonlocal calls`. Альтернатива без nonlocal — держать счётчик атрибутом `wrapper.calls`.

> [!hint]- Подсказка 3
> Скелет: `def rate_limited(max_calls): def decorator(func): calls = 0; @functools.wraps(func); def wrapper(*a, **kw): nonlocal calls; if calls >= max_calls: raise ...; calls += 1; return func(*a, **kw); return wrapper; return decorator`. Устная защита: назови по порядку все четыре темы, которые здесь встретились (замыкание, nonlocal, *args/**kwargs, wraps, исключения).
