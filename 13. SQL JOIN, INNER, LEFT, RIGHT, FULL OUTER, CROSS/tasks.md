## Ключевые идеи

1. ★ Любой JOIN с условием можно представить как перебор всех пар «одна строка слева + одна строка справа». В результат идут пары, для которых условие ON дало именно «истину». Каждая прошедшая пара становится отдельной строкой результата.
2. ★ INNER JOIN возвращает только прошедшие пары. Строка, у которой не нашлось ни одной пары (с любой стороны), исчезает из результата молча, без ошибки и предупреждения.
3. ★ LEFT JOIN возвращает те же пары, что INNER. Кроме того, каждую строку левой таблицы, не нашедшую ни одной пары, он добавляет ровно один раз, а столбцы правой таблицы у неё заполнены NULL.
4. ★ NULL в правых столбцах после LEFT JOIN может значить две разные вещи: «пары не было» или «пара есть, но ячейка в правой строке сама пустая». Отличить их можно только по столбцу правой таблицы, который в настоящих строках никогда не бывает пустым, обычно по её первичному ключу.
5. ★ Чтобы найти строки левой таблицы, у которых нет ни одной пары (анти-джойн), делают LEFT JOIN и оставляют строки, где первичный ключ правой таблицы `IS NULL`. Проверка `= NULL` не подходит: она всегда даёт «неизвестно», и фильтр выбросит все строки.
6. ★ Сравнение с NULL даёт «неизвестно», даже `NULL = NULL`. ON и WHERE пропускают только «истину», поэтому строка с NULL в ключе соединения никогда не находит пару.
7. ★ После LEFT JOIN строка без пары занимает одну строку результата. Поэтому `COUNT(*)` засчитает её как 1. Количество правых строк считают через `COUNT(столбец правой таблицы, который не бывает пустым)`. `SUM` по такой строке даёт NULL, и если нужен ноль, его оборачивают в `COALESCE(..., 0)`.
8. ★ Для каждого значения ключа число строк в INNER JOIN равно «сколько строк с этим значением слева» × «сколько справа». База не выбирает одну подходящую пару, потому что правила выбора у неё нет. Это знание о смысле данных, и его задаёт аналитик.
9. ★ LEFT JOIN возвращает не меньше строк, чем в левой таблице. Ровно столько же строк получается, только если у каждой левой строки не больше одной пары, например когда ключ справа уникален. Максимум равен произведению размеров таблиц. INNER JOIN возвращает от нуля до произведения размеров.
10. ★ Размножение строк не даёт ошибки, но завышает SUM, COUNT и AVG. Перед каждым JOIN нужно ответить себе на вопрос, что будет описывать одна строка результата (его гранулярность).
11. ★ Размножение проверяют двумя способами: сравнивают число строк до и после JOIN (потери и дубли могут взаимно замаскироваться) и запускают по присоединяемой таблице `GROUP BY ключ HAVING COUNT(*) > 1` (непустой результат значит, что ключ повторяется).
12. ★ Чинят размножение тем, что приводят присоединяемую таблицу к одной строке на ключ: либо оставляют одну строку по правилу, либо предагрегируют её в подзапросе. `DISTINCT` внутри агрегата лечит симптом, а не причину: он убирает повторы значений, а не повторы строк.
13. ★ Если к одной таблице приклеить подряд две таблицы со связью «один-ко-многим», повторы перемножаются, и неверными становятся обе метрики. Каждую такую таблицу агрегируют отдельно и только потом соединяют.
14. ★ При LEFT JOIN условие на правую таблицу в WHERE выбрасывает спасённые строки (сравнение с NULL даёт «неизвестно»), и запрос по факту превращается в INNER. То же условие в ON только сужает круг пар, а левые строки без пары всё равно сохраняются.
15. ★ При LEFT JOIN условие на левую таблицу в ON не убирает левые строки: не прошедшие условие строки просто останутся без пары. Чтобы отфильтровать левую таблицу, условие пишут в WHERE.
16. ★ Для INNER JOIN нет разницы, писать условие в ON или в WHERE: он не сохраняет строки без пары, поэтому в обоих случаях остаются одни и те же строки.
17. Один INNER JOIN в цепочке после LEFT JOIN выбрасывает строки, которые LEFT JOIN спас раньше. Если нужно сохранить все строки главной таблицы, все последующие соединения тоже должны быть LEFT.
18. RIGHT JOIN зеркален LEFT JOIN: `A RIGHT JOIN B` даёт те же строки, что `B LEFT JOIN A`. Поэтому на практике пишут LEFT и ставят главную таблицу первой.
19. FULL OUTER JOIN сохраняет строки без пары с обеих сторон. Он нужен для сверки двух источников, когда ни один из них не главный. Общий ключ из двух сторон собирают через `COALESCE`.
20. CROSS JOIN возвращает все пары без условия, по количеству это произведение размеров таблиц. Им строят сетку всех сочетаний (например, «объект × день»), к которой потом LEFT JOIN-ом приклеивают факты и проставляют нули. Нечаянный CROSS JOIN, например из-за забытого условия, раздувает результат до огромных размеров.
21. Self-join — это обычный JOIN таблицы с самой собой под двумя разными алиасами. Его используют, когда строка ссылается на другую строку той же таблицы или когда строки одного объекта надо сравнить между собой.
22. Чтобы self-join вернул каждую пару разных строк ровно один раз, ставят условие «номер слева меньше номера справа». Условие «не равно» оставит каждую пару дважды, в двух порядках.
23. `NOT IN (подзапрос)` возвращает пустой результат, если в подзапросе есть хоть один NULL. Анти-джойн через LEFT JOIN и `IS NULL`, а также `NOT EXISTS` от этого не страдают.
24. Кружочки (диаграммы Венна) показывают только то, чьи строки без пары выживают. Число строк они не показывают, потому что в них не отражается размножение.

### ★ Задача 3. Сколько строк вернёт каждый JOIN (рассуждение вслух)

**Идеи:** 6, 8, 9.

**Дано.** Таблица A, столбец `k`: 1, 1, 1, 2, NULL (5 строк). Таблица B, столбец `k`: 1, 1, 3, NULL (4 строки). Условие соединения: `A.k = B.k`.

**Что должно получиться.** Число строк для INNER, LEFT, RIGHT, FULL и CROSS JOIN. Для каждого вида нужен вслух проговорённый расчёт по значениям ключа: сколько строк слева, сколько справа, сколько пар, какие строки остались без пары. Отдельно две фразы: почему каждая из трёх единиц слева сочетается с обеими единицами справа и почему NULL слева не сочетается с NULL справа.

**Пример формата (на других данных).** A.k: 1, 2. B.k: 2, 2. Ответ: INNER = 2 (значение 2: 1 × 2 пары), LEFT = 3 (плюс строка 1 без пары), RIGHT = 2 (все правые нашли пару), FULL = 3, CROSS = 4.

**Ограничения.** Без запуска SQL, только рассуждением. Ответ оформить табличкой: значение ключа / строк слева / строк справа / пар.

> [!hint]- Подсказка 1
> Считай отдельно по каждому значению ключа: для него число пар равно «строк слева × строк справа» (идея 8). Потом добавь строки без пары: для LEFT только левые, для RIGHT только правые, для FULL и те и другие (идея 9). NULL рассматривай отдельно (идея 6).

> [!hint]- Подсказка 2
> Наивная ошибка — думать «LEFT вернёт 5, столько же, сколько в A» или «каждой единице слева достанется одна единица справа». На самом деле база проверяет условие для каждой пары отдельно. Пара «первая единица слева — первая единица справа» и пара «первая единица слева — вторая единица справа» — это разные пары, и обе дают «истину». Вторая ошибка — считать, что NULL совпадёт с NULL. Сравнение `NULL = NULL` даёт «неизвестно», а ON пропускает только «истину». CROSS JOIN условия не имеет вовсе, поэтому для него NULL ничем не отличается от других значений.

> [!hint]- Подсказка 3
> 1) Выпиши все значения ключа, встречающиеся хотя бы в одной таблице: 1, 2, 3, NULL. 2) Для каждого запиши, сколько строк слева и справа. 3) Посчитай пары; для NULL и для значений, которые есть только с одной стороны, пар 0. 4) INNER — сумма пар. 5) Найди левые строки без пары и правые строки без пары. 6) Собери LEFT, RIGHT и FULL из пар и строк без пары. 7) CROSS — произведение размеров таблиц.

### Задача 5. LEFT JOIN руками на чистом Python

**Идеи:** 1, 3, 6.

**Дано.** Сигнатура:

```python
def left_join(left: list[dict], right: list[dict], key: str) -> list[dict]:
    ...
```

Каждая таблица — список строк, каждая строка — словарь «название столбца → значение». Внутри одной таблицы у всех строк одинаковый набор столбцов. Столбец `key` есть в обеих таблицах, других совпадающих названий столбцов нет. `right` не пустой. Пустое значение обозначается `None`.

**Что должно получиться.** Результат LEFT JOIN по равенству `key`. Каждая прошедшая пара даёт одну строку: все столбцы левой строки плюс все столбцы правой, кроме `key`. Левая строка без пары появляется один раз, а правые столбцы у неё равны `None`. `None` в ключе не совпадает ни с чем, даже с `None`. Порядок: по порядку левых строк, а внутри одной левой строки по порядку правых.

**Пример.**

```python
left  = [{"id": 1, "name": "Аня"}, {"id": 2, "name": "Боря"}, {"id": None, "name": "Х"}]
right = [{"id": 1, "amount": 500}, {"id": 1, "amount": 300}, {"id": None, "amount": 100}]

left_join(left, right, "id")
# [{"id": 1,    "name": "Аня",  "amount": 500},
#  {"id": 1,    "name": "Аня",  "amount": 300},
#  {"id": 2,    "name": "Боря", "amount": None},
#  {"id": None, "name": "Х",    "amount": None}]
```

**Ограничения.** Без pandas и без сторонних библиотек. Достаточно перебрать все пары. По желанию напиши вторую версию, которая не перебирает все пары: заранее разложи правые строки по значению ключа и для каждой левой строки сразу бери нужную группу. Обе версии должны давать одинаковый результат на примере выше.

> [!hint]- Подсказка 1
> Нужно в коде повторить определение LEFT JOIN: перебор всех пар, отбор тех, где ключи равны, и добавление левых строк без пары с пустыми правыми столбцами (идеи 1 и 3). Особый случай — `None` в ключе (идея 6): в Python `None == None` даёт `True`, а в SQL это «неизвестно». Значит, этот случай нужно обработать явно.

> [!hint]- Подсказка 3

### Задача 8. Почему NOT IN вернул пустоту (провокационная, рассуждение вслух)

**Идеи:** 6, 23.

**Дано.** `users(user_id)`: 1, 2, 3. `orders(order_id, user_id)`: (10, 1), (11, 2), (12, NULL). Коллега ищет пользователей без заказов так:

```sql
SELECT user_id
FROM users
WHERE user_id NOT IN (SELECT user_id FROM orders);
```

Он получил пустой результат и говорит: «Значит, заказы есть у всех».

**Что должно получиться.**

1. Объясни по шагам, во что превращается условие для пользователя 3 и почему WHERE его выбрасывает.
2. Объясни, почему пользователи 1 и 2 тоже не попадают в ответ, но по другой причине.
3. Напиши два исправленных запроса, которые на этих данных вернут пользователя 3: через LEFT JOIN с `IS NULL` и через `NOT EXISTS`. Объясни, почему строка заказа с пустым `user_id` им не мешает.

**Пример «вход → выход».** На данных выше запрос коллеги вернёт пустой результат, а правильный ответ — одна строка: `3`. Если удалить из `orders` заказ 12, запрос коллеги тоже вернёт `3`.

**Ограничения.** Ответ «потому что NULL» без разворота условия по частям не засчитывается. Нужно проговорить исход каждого сравнения («истина», «ложь» или «неизвестно») и итог всего условия.

> [!hint]- Подсказка 1
> `NOT IN` по списку — это несколько сравнений «не равно», соединённых через «И». Один из элементов списка — NULL, и сравнение с ним никогда не даёт «истину» (идеи 6 и 23).

> [!hint]- Подсказка 3
> 1) Выпиши список, который вернёт подзапрос. 2) Для пользователя 3 разверни условие в цепочку «3 ≠ первый элемент И 3 ≠ второй И 3 ≠ третий» и запиши исход каждой части. 3) Вспомни, когда связка «И» даёт «истину», и определи итог. 4) Вспомни, что WHERE делает с «неизвестно». 5) Для пользователей 1 и 2 найди часть цепочки, которая даёт «ложь». 6) Для исправленных запросов подумай, что происходит со строкой заказа, у которой пустой номер пользователя: с кем она может сложиться в пару и влияет ли это на пользователя 3.
